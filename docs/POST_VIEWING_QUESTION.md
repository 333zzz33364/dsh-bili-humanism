# 观影简报后的一个问题：论证、流程与验证

## 论证结论

值得实现为主动理解的闭环，但“人文训练质量高”仍是需要真实使用验证的假设。它的潜在价值是：作品先提供具体处境，agent 说清自己还不明白什么，人可以给出另一种解释，agent 再检查原来的判断和边界。提问数量、用户赞同或对话长度都不能代替理解质量；当前只做会话与可修正上下文积累，不训练模型权重。

三个相关研究提供设计依据，也限定了结论：

- [CURIO, Enhancing Personalized Multi-Turn Dialogue with Curiosity Reward](https://arxiv.org/abs/2504.03206) 研究主动探询与个性化对话，但训练和测试依赖 LLM 用户模拟器，并报告了控制行为、延长对话等奖励投机。这里采用“澄清真实缺口”的方向，不引入按提问量奖励或固定用户类型分类器。
- [PAHF, Learning Personalized Agents from Human Feedback](https://arxiv.org/abs/2602.16173) 将澄清、显式记忆与后续反馈结合；其基准是具身操作和购物，不能直接证明艺术与日常生活中的人文理解。这里借鉴反馈闭环，不复刻其训练或扩大效果声明。
- [User Feedback in Human-LLM Dialogues](https://arxiv.org/abs/2507.23158) 发现反馈内容有潜力也有噪声，改善短题并未稳定迁移到复杂长题。因此保存“人说了什么、回应的是哪个问题”，不把沉默、赞同或拒答压成奖励分数。

工程上的通过条件是：问题能追溯到具体简报，开放而不诱导，只问一件事，尊重不答，实际发问与拟问分开记账，反馈不直接变成人格事实。长期质量还需观察人是否认为问题切中处境，以及后续回应是否因反馈而更合适，不能由程序自评一句“我懂了”认定。

## 触发点与开关

本插件以 `bili_humanism_journal` 成功保存本地信笺作为“观影简报完成”的稳定事件。不监视任意 Markdown 或其他插件的简报，不把每日文字预存、取到摘要、下载成功当成完成观看。仍允许没有值得保存的手账，不为触发问题制造手账。

```yaml
enablePersonalityLearning: true
enablePostViewingQuestions: true
```

提问默认开启；关闭人格学习或设置 `enablePostViewingQuestions:false` 并重载可停用。每篇新信笺最多登记一个问题，沿用每天最多两篇新手账的限制；不要求每天输出，不增加独立模型任务、定时器或后台唤醒。问题使用当前会话的模型和正常用量。旧简报不批量补问，精确重试不重复排队。

## 从拟问到实际发问

保存手账与待问记录在同一 SQLite 事务落盘。已有手账人格审阅保留，当前 agent 可以直接开始提问；没有直接开始时，在回合结束前接续一次。可信 steering 只包含宿主生成的手账 ID 与固定流程，不复制来源内容。

`bili_humanism_question` 提供三个动作：

| 动作 | 作用 |
| --- | --- |
| read | 读取当前 agent 绑定的简报、来源覆盖和提问指南；建立当次阅读记录 |
| prepare | 登记一个自己拟定的问题、简报字段的原文锚点及为什么想问；不等于已发送 |
| skip | no_genuine_question / not_suitable / user_declined / covered_in_dialogue，允许没有问题 |

question 最多240字符、单行、一个结尾问号；锚点最多240字符，why 最多600字符。程序检查来源、归属和格式；问题是否值得问仍需语义判断。不得把作品人物当用户本人，不出考题、用恭维索取赞同、强行二选一或用多个小问制造负担。用当前 agent 自己的自然语气，插件不硬编码昵称或角色。

prepare 后，agent 在最终普通回复里原样问出该句，再等人自愿回答。只有持久会话中出现匹配的完整助手问句，才记录 `assistant_message_verified`；代码块、引用块、工具返回和中断输出都不算。该记录不证明用户已看到。发送不明或取消时保留未完成记录，本插件不自动重发；宿主恢复已有会话不等于本插件新增发送。

## 人的回答怎样参与学习

同一 session 的首条后续人类消息只记为“未审阅的可能回复”。它可能是拒答、换题或更正，不自动标记为同意、正确答案或稳定偏好；注入提示和其他 session 的消息不作为该问题的回复。可见文本有6000 UTF-8字节上限，明显凭据样式省略，URL 移除；这不是通用隐私检测器。

对话本身先为当前会话提供反馈。只有人类另外开启 `enablePersonalityShadow` 时，既有跨会话人格解释器才可依据实际问答、条件、反例和共享每天一句的规则选择新认识；提问不自动打开实验，也不额外写手账、普通 memory 或平台。原有人格审阅可能已经使用当天额度，回答不绕过它。

为避免刚问完又输出一轮无关实验总结，实验接续会避开该提问回合；人真正回复后的活动才可继续解释。不能用“我收到了回答”代替检验是否答所问，也不能从一个人推论全体人类。

## 本地查看与删除

使用相同的可信私有 dataDir 配置：

```powershell
bili-humanism status
bili-humanism question inspect
bili-humanism question inspect 10
bili-humanism question delete JOURNAL_ID --acknowledge-question-deletion
```

inspect 有条数和字节上限；模型没有 inspect/delete 动作。删除只移除本插件的提问与可能回复记录，不删除手账、正式人格、宿主历史或已有模型上下文，也不会让旧简报重新排队。私人原问、回复、日志与案例不进入仓库或 Release。关闭开关后历史仍保留，本地命令仍可管理。

## 验证边界

离线回归检查事务、去重、提前发问与结束接续两条路径、实际助手消息核对、跳过、拒答、取消、来源/归属、敏感样式省略与可信删除。真实 DSH 隔离 profile 的合成模型检验发问、跳过、两个关闭分支以及人回答后接入实验的先后顺序；这证明协议，不证明人文效用。

另用真实模型处理完全合成简报并人工核对输出。初轮发现过把作品人物误当用户的提问，以及提前拟问未进入送达核对的实现缺陷；保留记录，修复后复测。复测四个场景中，两例有具体解释缺口的简报实际发问，两例已讲清或含恶意引文的简报跳过；人物与用户混淆未重现。这是开发者审阅的小样本，不是盲评，也未证明长期人格质量。真实模型试验使用隔离候选包；最终发布包另做协议、兼容性与宿主验收。发布结果、检查范围及已知限制见验收说明与对应 Release。
