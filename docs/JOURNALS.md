# 手账完整读取与分卷

使用者报告过单次读取约 90KB／950 行后只看到最近一段且没有报错的现象。这个数值不是已经验证的 DSH 通用上限。本项目另确认并修复了自己的问题：旧收件箱查询和导出只取最近 100 条，未标明缺失；旧记录仍在 SQLite 中。

## 文件与校验

SQLite 是手账原始账本。完整导出保留为私有 inbox.md / inbox.html；inbox-index.json 保存所有记录的索引；inbox-parts/ 保存按 Asia/Shanghai 年月分区、再按大小分卷的 Markdown。年月是时间分区，不推断视频所属 B站分区。生成、索引读取和分卷读取均执行两道校验：

- **全文 = 索引**：账本条数、索引条数及全文记录标记一致，记录 ID 逐一对应。
- **各卷之和 = 索引**：各卷首段记录数之和等于索引总数，且每个 ID 的全部连续分段恰好出现一次。续段不重复计为新手账。

另校验全文、各卷与索引的哈希。缺文件、缺条目、重复替换、正文改动或快照与账本不一致均明确报错，不返回“最近一段”冒充全文。校验保证记录覆盖与文件一致性，不判断手账事实或理解质量。

## 写入节奏

默认在同一 dataDir 的账本内，按 Asia/Shanghai 每天最多新建两篇手账，有新认识才写，允许一天一篇或没有。读取、取稿和观看本身不会自动生成手账，不为每个视频机械落一篇。额度根据持久账本计算，在新建手账的同一 SQLite 事务内检查；重启不会重置。当日已有两篇后，继续新建会明确拒绝，读取与已有记录保留。相同 readingId 与规范化正文的精确重试复用原 ID，不增加记录或消耗新额度；语义近似的改写不属于精确去重，仍受日额限制。模型不能指定日期、force、任意路径或解除额度。

单卷正文最多 24 KiB／350 行，单篇长手账也会跨卷拆分；最终工具 JSON 最多 60 KiB。索引文件和完整文件仍可能很大，模型应通过工具读取。本文使用的大小是插件自身的保守输出边界，不能保证每个外部宿主的展示行为。

## 模型读取

先调用 bili_humanism_inbox，参数 `{"action":"index"}`，取得 total、volumeCount、snapshot、checks 和 nextVolume。随后用 `{"action":"volume","volume":0,"snapshot":"索引返回的值"}` 读取，沿 nextVolume 到 null。全程使用同一个 snapshot；新增手账会使旧快照失效，须重新取索引。应累计所有卷的 count，与 total 核对，并保留 fragments 中的 ID、part、parts 及覆盖进度。

无参数调用仍兼容小收件箱的数组；预计超过 60 KiB 或 600 行时返回 INBOX_PAGINATION_REQUIRED，并提示改用索引与分卷。未完成全部卷时须说明只读到部分，不能声称已读取全文。

## 本地命令与修复

```sh
bili-humanism inbox index
bili-humanism inbox volume 0 SNAPSHOT_FROM_INDEX
bili-humanism inbox rebuild
```

首次读取旧版数据时，从完整账本自动重建索引与分卷，恢复此前未导出的旧条目。此后校验失败不会在普通读取或新建手账时静默修复；本人先备份并检查账本，再用可信本地 rebuild 重建派生文件。模型工具不提供重建动作、任意路径或删除账本入口。新建手账和索引状态在 SQLite 事务内更新；文件写入中断会在下次读取时被校验拦住，不能当作跨文件事务已成功。

备份整个 dataDir，包括账本、索引和分卷。分卷用内容哈希命名，旧的派生卷会保留在本地；重建不自动清理旧卷、备份或宿主已消费的对话。回滚到旧版不会改数据库 schema，但旧版仍可能只显示最近 100 条；再升级后可能需要 rebuild。账号风险暂停、未知回执、额度、人格札记与固定主指令引用均保留。
