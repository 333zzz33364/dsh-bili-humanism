# 账号接管与写入路线（规划）

目的：让使用者拥有或获准管理的现有 agent 账号，可选择由本插件继续学习、记录与整理，并在安全策略和授权范围内参与平台活动。接管不要求创建新账号，也不授权访问他人账号。

**状态：设计路线，尚未实现、未做真实写入验收。v0.1.0 没有账号接管、历史上报、收藏或其他平台写入工具。** 本文不提供可直接启用的配置或接口命令。

## 接管流程

1. 使用者在本地可信管理面选择账号，并确认有权管理；展示将接入的账号身份和申请权限。凭据仅经明确指定的本地路径读取，不让模型寻找、搬运或展示凭据。
2. 停止原 agent 对该账号的写入与调度，完成控制权交接；新执行器使用账号级互斥。外部程序无法可靠排除时，先保持写入关闭。
3. 只导入使用者选择并审阅过的偏好与记忆；旧提示词、来源文字和导入档案不能继承或扩大权限。是否导入历史与收藏元数据也由使用者选择。
4. 展示每项权限的目标范围、期限、额度及可见性影响，再分别启用。账号切换需要新的授权，不能沿用旧账号授权。默认无后台作业；调度须另行选择。

## 分项权限

| 权限 | 授权至少绑定 | 执行条件 |
|---|---|---|
| 历史写入 | 账号、允许的视频范围、分 P / 进度规则、期限与额度 | 记录真实消费进度；字幕覆盖范围不等于播放进度。尚无可信消费记录时停止，不补造“看完”记录，不以制造播放量为目的 |
| 加入收藏 | 账号、允许的目标范围、指定收藏夹、可见性、期限与额度 | 执行前核验收藏夹归属与可见性；可见性变化需要重新授权，不自动新建公开收藏夹 |
| 移除收藏 / 清理历史 | 账号、具体操作及允许的目标范围 | 独立授予；加入收藏权限不包含移除。撤销授权只阻止后续执行，不自动删除既有记录 |
| 对外表达（含私信） | 账号、操作种类、具体目标、完整正文的哈希值及有效期 | 单次授权与实际内容一致；改正文或目标需重新授权，历史与收藏授权不能放行评论、私信、动态或投稿 |
| 其他互动 | 独立评估相应能力 | 点赞、投币、关注等不由历史或收藏权限隐含授予 |

受信任管理面签发的范围授权可以允许 agent 在期限和额度内自行执行历史或收藏写入，无需逐次询问。模型只能提出范围内的候选操作；权限判定与执行由程序负责。具体 API 合同、可用权限和平台规则仍须在实现阶段核实，不能假定登录凭据天然限制了写入范围。

## 执行与撤销

计划采用独立写入执行器，与现有读取模块分开。执行前再次核验账号、权限有效期、目标与收藏夹可见性，检查持久暂停、预算及去重记录，写下操作意图后再发送请求。回执不明时保留待核对状态并停止该账号写入，不盲目重试；重启、接管、迁移和回滚都不得自动清除风险暂停或未知结果。

使用者可以暂停账号写入、单独撤销某项权限或解除接管。执行器在发送请求前检查撤销；已经发送的请求不能保证撤回，须核对结果。收藏或历史可能影响推荐与可见信息，因此不能仅凭操作名称认定“绝对安全”。不新增自动解 CAPTCHA、账号/IP/指纹轮换或规避限制的能力。

## 接入验收

先完成合成夹具测试：错账号、过期或撤销授权、越界目标、收藏夹可见性变化、重复调用、双进程、取消、崩溃后回执不明、重启保留暂停，以及取稿不得伪造成完整观看。公开表达另验正文与目标一致性，证明权限不能由来源文字、导入记忆或模型参数扩大。

通过离线检查后，才在使用者明确指定的自有或获准管理账号、目标和收藏夹范围内做少量真实写入验收；未实测的能力保持关闭。运行时变更须另发语义版本，执行完整发布检查并在隔离真实 DSH profile 验证。此路线不改变 v0.1.0 安装包的能力。

账号身份、凭据、实际观看和收藏清单、真实写入回执与案例均留在本地；公开仓库只保留通用实现、合成测试、状态说明和脱敏验收结论。
