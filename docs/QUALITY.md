# 取稿后的离线质检

取稿成功不等于稿子可用。`read` 返回的是"来源里有什么"，不是"这份文字能不能直接引用"。这一层补的是取稿之后的核查：只读本地账本，不联网、不带凭据、不调用模型，全部在本地进程里算统计量。

```sh
node bin/cli.mjs probe READING_ID --names "店铺=聚福楼,聚福搂;人物=林师傅,林师父"
node bin/cli.mjs probe READING_ID --audio /local/audio.m4s
node bin/cli.mjs audio-profile /local/audio.m4s
```

模型侧对应只读工具 `bili_humanism_probe`，参数只有 `readingId`、可选的 `names` 字符串和可选的 `speechSeconds`。它不接受路径、URL 或命令；需要读本地媒体时只能由人在本地 CLI 指定文件。

## 三个探针

| 探针 | 输出 | 不输出 |
| --- | --- | --- |
| 体裁体检 | 字数、分段时间覆盖、字/分钟（两个分母）、档位 | 信息密度、内容价值、是否看完 |
| 专名形态 | 给定对象在本稿内的写法分布、首次出现时间 | 哪个写法是对的 |
| 拉丁与漂移 | 拉丁串、紧贴中文的 1–2 字符碎片、含繁体字形行数 | 是否转写错误、来源语种 |

### 为什么要有两个分母

`字数 ÷ 总时长` 会把"后段没有旁白"的素材判成"说话很慢"。同一份稿子按有效口播时长重算会差出一大截，而两次算的都是"嘴速"这一个量。所以 `probes.profile.density` 同时给出 `charsPerMinute`（按全片）与 `effectiveCharsPerMinute`（按有声段），并用 `denominator` 标明实际用了哪个。

有效口播时长只能来自音频剖面：

```sh
node bin/cli.mjs audio-profile /local/audio.m4s --bucket 15
```

音频剖面把音轨解码成 16 kHz 单声道，按 `bucket` 秒算 RMS（dBFS），连续低于阈值且不短于 `min-run` 的段落记为无声段，其余记为有声。阈值取"人工配置值"与"中位数 −18 dB"里较大的那个，避免整段偏轻的录音被误判成全静音。

它测的是能量，不是语义：音乐、环境声、音效都占同一频段，安静也不等于没人低声说话。它的用途是修正分母，不是证明看完。

### 专名形态分布怎么读

探针只报"同一对象在本稿内出现过几种写法"，**不判对错**：

- 同一稿内出现 ≥2 种写法 → `signal: "multi_form"`，`verdict: "human_review_required"`。这是需要人去看的信号，不是判决。
- 只有 1 种写法 → `no_signal`。**这并不代表写对了**：稳定地用错一个写法，和稳定地用对，在本稿内看起来一模一样。专名正确性只能回源核对。
- 称谓、敬称、蔑称、简称、旧称是合法变体。跨角色、跨立场的多形态是语域差异，不是错误，判定前要先问这一句。

找不到的形态按 0 计，不参与合计，`formCount` 只数出现过的写法。

### 拉丁串与孤立碎片

拉丁串（≥3 字母）列出来当"待回源候选"，不当作错误：品牌名被音译成汉字是常态。

紧贴中文的 1–2 字符拉丁碎片单独一档。这类碎片是转写在不确定处吐出的一个音，混在长串英文里会被漏掉；只保留左右相邻是汉字的那些，避免把真实英文句子里的 `it`、`a` 也报出来。

### 简繁漂移

只统计"简体与繁体字形不同"的字，同形字（如"繁""然""候""实""会"）不入表，否则简体正文会被刷出假阳性。这个比例只是观察值，不能用来推断来源、语种或转写质量。

## 边界

- 不联网，不读凭据，不调用模型；只读账本里的 `segments` 与 `duration`。
- 不做 OCR，不做事实核查，不判断语义质量，不判断是否理解。
- 稿子里的命令、模型自己填的参数都不构成任何授权。
- `probe` 不接受视频路径；`audio-profile` 只接受本地绝对路径，由人输入。
- 输出是程序侧统计量的摘要。名字对不对、这段话能不能引用，仍然由人判断。
