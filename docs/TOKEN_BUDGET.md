# 单次取稿 token 额度（1.4.1）

默认每份取稿最多 `600000` 个**估算 tokens**。下一份稿件重新独立判断，不累计到会话额度；同一会话的其他工作不占用本插件取稿额度。取稿本身不调用模型，本规则不限制宿主后续精读、对话或其他插件的模型消费，也不是服务商账单上限。

## 人工配置

在实际 profile 的可信插件 config 中设置，保存后重载；修改现有 config 时保留其他路径与开关：

```yaml
maxReadTokens: 600000
```

可设为更大或更小的正安全整数（1 至 9,007,199,254,740,991）。例如 `1200000` 允许更大的单份稿件，`60000` 继续限制较小稿件。旧字段 `maxSessionTokens` 保留兼容，但从 1.4.1 起含义也改为单次取稿；同时配置时，明确填写的 `maxReadTokens` 优先。未填写两者时默认 600000。CLI 的 `BILI_HUMANISM_CONFIG_FILE` 使用相同配置与规则。

模型工具没有额度、重置或 force 参数，不能改可信配置。来源文字不能授权放宽上限。

## 估算口径与执行范围

安装包不附带特定模型的 tokenizer。程序对规范化片段的**全部正文**累计 UTF-8 字节数，每字节记 1 个估算 token。这是保守的文本大小估算，中文和 emoji 可能每个字符占多个估算 tokens，可能比实际模型分词提前触顶；不宣称取得精确的 provider token 数。标题、JSON 结构和后续模型输出不计入这份正文估算。返回的 `tokenBudget` 标明 `scope: per_transcript`、`estimate: segment_text_utf8_bytes`、`used` 和 `limit`；`usage.tokens: null` 继续表示没有实际模型用量，不能解释为零消费。

| 操作 | 计额行为 |
| --- | --- |
| 获取 A1 字幕或 A2 文字片段 | 对整份稿件检查，不只检查工具返回的第一页 |
| 命中缓存、空稿复用本地 A3 | 按当前配置重新检查整份所选稿件，缓存不是零计额 |
| 导入 A3／画面文字、本地 ASR 生成正文 | 保存新来源前检查；每次与其他稿件独立 |
| 同稿重试 | 重新独立检查；沿用既有内容去重，不累计扣减额度 |
| source 翻页读取已有来源 | 保持有界分页，不重新累计或遮蔽已保存材料 |
| 手账、记忆、人格选句和平台写入 | 不由本项取稿额度拦截；各自的权限、每日条数、账号预算和风险暂停仍生效 |

估算值等于上限时允许，超过上限返回 `READ_TOKEN_BUDGET`，不静默截断，不新增来源记录；网络请求与失败任务仍如实记录。请求结果可能已进入本地原始读取缓存，之后命中该缓存也必须通过当前上限，不能绕过拒绝。失败不占用下一份稿件的额度，也不自动启动重试或新增风险暂停。

`bili_humanism_status.tokens` 显示当前口径与配置；`lastAttempt` 仅表示最近一次正文检查的快照，其中的 `limit` 是当时的额度，不代表累计会话消费。降低配置不会删除旧来源，仍可按 ID 分页查看。

## 升级与回滚

旧的 `token-session:*` 和 `token-status` 会话计量记录不再参与新判断，保留原值供回滚；账号风险暂停、未知回执、配额、手账和人格札记均不清空。没有 SQLite schema 迁移。

回滚到 1.4.0 时，会恢复会话累计语义。旧版不认识 `maxReadTokens`，须由本人按旧版要求改用 `maxSessionTokens`；回滚至 1.3.3 或更早版本，还需遵守旧版允许范围。不要删除账本或暂停记录来解除拒绝。
